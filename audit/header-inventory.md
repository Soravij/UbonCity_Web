## Cross-cutting notes (item 4 detail)

- **Favicon block** (`place.html:6-9`): zero JS references anywhere (`grep favicon\|apple-touch-icon` on `app.js` — no matches). Safe to delete/move to a shared partial with no JS-side consequence.
- **`.auth-row h1` / `.auth-row p`** are used as *structural* selectors, not cosmetic ones — six page-scripts (`article-intake.js`, `article-workspace-page.js`, `event-submit-page.js`, `event-workspace-page.js`, plus `article-workflow-core.js` shared by others) inject dynamic title/subtitle text into them. Renaming these classes without updating every listed file breaks visible page titles, not just styling.
- **3 dead pages** (`transport-map-routes.html`, `transport-map-review.html`, `transport-map-workspace.html`) still carry full header markup, but their paired page-scripts are one-line `window.location.replace(...)` redirects to `transport-v2-*` equivalents — the header never renders to a real user. A 4th page, `transport-v2-workspace.html`, is the same dead-redirect pattern but via an inline `<script>` in `<head>` with no header markup at all.
- **2 pages** (`transport-v2-path-editor.html`, `transport-v2-routes-review.html`) are intentionally header-less full-screen editor/review canvases — confirmed by their explicit empty-string `authNodeId` argument to `requireAdminShell()`, not an oversight.

## Item 5 detail — static vs. templated (`collector/server/index.mjs`)

- `collectorPublicDir = server/public` — `index.mjs:151`.
- `index.mjs:2738-2746` — middleware runs on **every** GET/HEAD request before `express.static`: `isSafeCollectorHtmlRequestPath` (172-173, regex `/^\/[A-Za-z0-9._/-]+\.html$/i`) + `resolveCollectorHtmlFilePath` (176-183) match any `/*.html` path that exists under the public dir, and call `renderCollectorHtmlFile()` (185-188), which reads the raw file and runs `rewriteCollectorHtmlAssetUrls()` (247-252) — a regex rewrite of every `src=`/`href=` attribute to append/refresh a `?v=<version>` query string (`withVersionQuery`, 224-245, resolving `__COLLECTOR_ASSET_VERSION__` or file mtime). **This applies to all 27 `.html` files**, not just `index.html`.
- `index.mjs:2747-2755` — an analogous middleware for `.js`/`.mjs` requests: `resolveCollectorJsFilePath` (194-201) + `rewriteCollectorModuleSpecifiers` (254-264) rewrite version-query strings on `import`/`export`/dynamic-`import()` specifiers inside JS source before serving. So the JS files aren't pure static passthroughs either.
- `index.mjs:2756` — `app.use(express.static(collectorPublicDir, { index: false }))` is the fallback for anything that didn't match the two regexes above (`.css`, `.png`, `.ico`, `.svg`, etc.) — those are the only assets served as literal untouched bytes.
- `index.mjs:2757-2761` — `app.get("/")` calls `renderCollectorRootHtml()` (266-269), which reads `public/index.html` and applies the **same** `rewriteCollectorHtmlAssetUrls` function used for every other `.html` file. `/` and `/index.html` receive identical treatment via two different route entry points into the same rewrite function.
- **No template engine** (no EJS/Handlebars/etc.), **no partials/includes**, **no conditional server-side logic** anywhere in these routes — the only transformation is asset-URL version-stamping.

## Synthesis

Of the 27 pages: **5** match the "full auth UI" pattern (`place.html`, `index.html` with variant `#auth-status`, `events.html`, `editor-home.html` with variant `#portal-auth-status`, `freelance-home.html` with the same `#portal-auth-status` convention as editor-home). **14** are "header-row only" (`.auth-row` + `#workspace-auth-status`, no `.auth-box`), of which **3** (`transport-map-routes/review/workspace.html`) are dead legacy pages whose header markup never renders in practice because their page-scripts are one-line redirects to `transport-v2-*` equivalents. **3** use variant auth-status ids on the same header-row shape (`clean-item.html`, `field-brief.html`, `item-editor.html`). **2** have no header at all (`article-preview.html`, `event-preview.html`). **2** are standalone full-screen editor/review canvases with intentionally no header (`transport-v2-path-editor.html`, `transport-v2-routes-review.html`). **1** is a pure inline-script redirect stub with no body content (`transport-v2-workspace.html`).

Only `place.html` has the favicon block, and it has zero JS coupling, so it can be lifted into a shared partial on its own with no risk.

A shared header component is architecturally feasible, but **not** as a build-time static include: `index.mjs:2738-2746` and `:2757-2761` prove the server already treats every `.html` file as text rewritten per request, not a byte-for-byte static asset. Extending that same rewrite pass to splice in a shared header fragment (e.g. replacing an `<!--HEADER-->` placeholder before the existing `rewriteCollectorHtmlAssetUrls` call runs) is a natural, low-risk extension point — it doesn't require introducing a templating engine, since one doesn't exist today and none of the routes do conditional logic or partials. What would **not** work is a naive client-side-only or build-step approach that assumes these files are pure static bytes: they aren't, and any shared-header approach must account for the version-query rewriting these routes already perform on `src`/`href` attributes, or ordering/double-rewrite bugs will result. Any migration also has to preserve the id-variant auth-status elements (`#auth-status`, `#portal-auth-status`, `#editor-auth-status`, `#brief-auth-status`) exactly as-is per page, since each is a hard dependency of a specific JS file — a shared component cannot standardize on a single id without also touching `app.js`, `editor-home.js`, `freelance-home.js`, `item-editor.js`, and `field-brief.js`.
